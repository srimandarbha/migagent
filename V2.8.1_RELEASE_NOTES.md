# Migration Failure Agent v2.8.1

## Focus
Test-harness semantics and diagnostic-agent hardening only. No remediation execution, EDA, AAP, ServiceNow, retry, rollback, or autonomous recovery was added.

## Changes
- Memory matrix modes are now real execution inputs: `both`, `sre`, `rhokp`, `none`.
- Disabled SRE Tracker/RHOKP sources are not injected into the agent.
- Current failure case is excluded from historical SRE memory, preventing self-contamination.
- Diagnosis basis explicitly separates current authoritative evidence, SRE history, RHOKP knowledge, and advisory sources.
- Structured investigation recommendation added to AgentState.
- Recommendation is explicitly investigation-only and states that remediation/retry must not be executed by this agent.
- Capability results expose capability status and result semantics separately.
- Local Splunk fixture adapter correctly maps `fact_code` to `fact`.
- Network NAD and VMware CBT policies no longer require generic migration-state evidence as a diagnostic gate.
- Matrix runner now checks memory enablement, disabled-source leakage, and diagnosis invariance across memory modes.
- CSI timeout diagnosis now reflects backend-unhealthy evidence instead of incorrectly stating the backend is healthy.

## Validation
- Python compilation: passed.
- Unit/regression tests: `19 passed, 1 skipped`.
- Direct matrix: `24 total, 24 passed, 0 failed`.
- Matrix covers 6 scenarios x 4 memory modes.

## Known limitation
The current RHOKP fixture corpus is a local test dataset, not a production RHOKP connection. Knowledge presence in the matrix proves adapter isolation and retrieval plumbing, not production retrieval quality. Real Red Hat issue corpus validation remains a later phase.
