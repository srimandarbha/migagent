# v2.8 Matrix Testing

`run_v28_matrix.py` is the repeatable evaluation entry point.

## Direct mode

Fastest development loop:

```bash
python scripts/run_v28_matrix.py --mode direct
```

One scenario:

```bash
python scripts/run_v28_matrix.py --mode direct --scenario storage-csi-backend-healthy
```

One memory condition:

```bash
python scripts/run_v28_matrix.py --mode direct --memory none --provider openrouter
```

The current v2.7 engine does not yet implement memory isolation. The runner records the requested memory mode so the v2.8 memory adapters can be introduced without changing the test format. Do not treat the four memory modes as genuinely isolated until the v2.8 memory implementation is wired.

## Kafka end-to-end

Start the Kafka agent first:

```bash
python scripts/run_kafka_agent.py
```

Then run:

```bash
python scripts/run_v28_matrix.py --mode kafka
```

The runner creates a unique event id for every case, publishes `MigrationFailed`, and waits for the matching `MigrationFailureAgentResult`. It ignores unrelated result messages.

## Results

The default machine-readable report is:

```text
results/v28-matrix-results.json
```

A test passes only when every configured assertion passes. A timeout, Kafka error, malformed result, or assertion mismatch is a failure.
