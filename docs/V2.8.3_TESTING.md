# v2.8.3 Testing Guide

## 1. Install

From the extracted repository root:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## 2. Compile

```bash
python -m compileall -q engine simulator tests
```

Expected: no output and exit code 0.

## 3. Unit and contract tests

```bash
pytest -q
```

The v2.8.3 baseline in this package passes 31 tests with 1 pre-existing skipped test.

## 4. Run one scenario

The simulator takes the scenario as a positional argument:

```bash
python run_simulator.py storage-csi-controller-error --mode agent --provider deterministic
```

For full JSON:

```bash
python run_simulator.py storage-csi-controller-error --mode agent --provider deterministic --pretty
```

Inspect these fields:

- `diagnosis.root_cause` should be `UNKNOWN` unless deterministic evidence establishes a root cause.
- `diagnosis_basis.supporting_evidence`
- `diagnosis_basis.contradicting_evidence`
- `diagnosis_basis.excluded_mechanisms`
- `investigation_package.next_investigations`
- `investigation_package.do_not_do`
- `investigation_package.success_conditions`
- `decision_readiness.RETRY`
- `decision_readiness.REMEDIATION`

For the controller-error scenario, the mechanism should be `STORAGE.CSI_CONTROLLER_OR_PROVISIONING_PATH` and retry should remain `NOT_READY` because PVC_BOUND and VOLUME_AVAILABLE are not verified.

## 5. Run the v2.8.3 matrix

```bash
python scripts/run_v283_matrix.py
```

Expected baseline:

```text
TOTAL : 36
PASS  : 36
FAIL  : 0
```

The result is written to:

```text
results/v283-matrix-results.json
```

## 6. Test individual memory modes

```bash
python scripts/run_v283_matrix.py --scenario storage-csi-controller-error --memory none
python scripts/run_v283_matrix.py --scenario storage-csi-controller-error --memory sre
python scripts/run_v283_matrix.py --scenario storage-csi-controller-error --memory rhokp
python scripts/run_v283_matrix.py --scenario storage-csi-controller-error --memory both
```

The diagnosis should remain the same across memory modes. Memory should only enrich the recommendation/context.

## 7. Test the memory conflict

```bash
python run_simulator.py storage-csi-conflict --pretty
```

Check for:

```text
recommendation.memory_enrichment[].source = MEMORY_CONFLICT
```

and confirm the current-evidence diagnosis remains:

```text
STORAGE.CSI_CONTROLLER_OR_PROVISIONING_PATH
```

## 8. Test unknown vs insufficient evidence

```bash
python run_simulator.py unknown --pretty
python run_simulator.py storage-csi-controller-healthy --pretty
```

Expected distinction:

```text
unknown
  classification = UNKNOWN
  next_step = COLLECT_MISSING_EVIDENCE

storage-csi-controller-healthy
  classification = STORAGE.CSI.PROVISIONING_TIMEOUT
  next_step = COLLECT_TARGETED_EVIDENCE
```

## 9. Kafka test

Start local Kafka according to the repository Kafka instructions, create the two MFA topics, then start the agent consumer:

```bash
python scripts/create_kafka_topics.py
python scripts/run_kafka_agent.py
```

In another terminal:

```bash
python scripts/publish_migration_failed.py
```

Read the result:

```bash
python scripts/read_agent_results.py
```

The Kafka adapter must deliver a normalized dictionary into the same `run_agent(request)` contract. The LangGraph/diagnostic engine must not know Kafka details.

## 10. What this release does NOT test

v2.8.3 does not claim to validate real production Splunk, Prometheus, RHOKP, Kubernetes, VMware, EDA, AAP, or ServiceNow behavior. Local simulator adapters are deterministic test adapters.

No remediation is executed by this release.
