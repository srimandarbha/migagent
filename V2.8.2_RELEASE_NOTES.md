# Migration Failure Agent v2.8.2

## Scope
Harness and agent hardening only. No remediation or automation execution is introduced.

## Changes
- Added explicit `mechanism` to diagnosis to separate failure class from failure mechanism.
- Added `decision_readiness` as the forward-compatible name for legacy recovery readiness. The agent remains read-only.
- Added memory provenance priority: current evidence, SRE history, RHOKP knowledge, LLM advisory.
- SRE Tracker and RHOKP results now enrich the investigation recommendation with provenance instead of influencing diagnosis.
- Added conflict handling when historical resolution differs from the current evidence-supported mechanism.
- Added evidence variants for CSI provisioning timeout: backend degraded, controller error, and controller state unavailable.
- Added a Red Hat troubleshooting source record for MTV 2.11 documentation.
- Expanded the matrix to 36 cases across four memory modes.
- Added v2.8.2 unit tests for memory isolation, memory usefulness, conflicting history, fail-closed behavior, diagnostic-only recommendations, and knowledge provenance.

## Safety invariant
Current authoritative evidence determines diagnosis. Historical SRE records and RHOKP retrieval can add context but cannot vote against or override current evidence.
