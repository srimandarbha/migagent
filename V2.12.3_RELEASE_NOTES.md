# v2.12.3

## Taxonomy & Policy Decoupling
- Decoupled `GUEST.WINDOWS.VSS` from CBT into dedicated `policies/guest.windows.vss.yaml` and `skills/guest/windows-vss/skill.md`.
- Separated `VMWARE.VCENTER.CONNECTIVITY` (TCP 443 / SSL thumbprint) from `VMWARE.ESXI.CONNECTIVITY` (TCP 902/NFC/443).
- Added dedicated policies and skills for 16 failure taxonomy classifications:
  - Windows VSS, Hivex registry corruption, BitLocker encryption/VMK metadata, KubeVirt EFI/BIOS firmware conflict, Linux Btrfs filesystem, VDDK transport permission Error 13, VDDK NBD data source export, CD-ROM VMX entry, virt-v2v OOM, argument list E2BIG, Windows NTFS filesystem read-only, disk image resize failure, VirtIO storage drivers, VMDK datastore path, and VMware credentials unauthorized.

## Generic Declarative Hypothesis Engine
- Replaced hardcoded Python `if/elif` hypothesis logic in `MigrationFailureEngine._hypotheses()` with a declarative schema in policy YAML files (`hypotheses:`).
- Evaluates `supporting.all`, `supporting.any`, `contradicting.all`, and `contradicting.any` against live facts.
- Explicit status tracking: `SUPPORTED`, `CONTRADICTED`, and `UNTESTED`.
- First-class contradiction handling: contradictory facts immediately exclude mechanisms and automatically populate `diagnosis_basis['excluded_mechanisms']` with provenance evidence IDs.

## Capability Coverage Hardening & Safety Gating
- Added policy-vs-registry capability coverage preflight (`calculate_coverage`).
- Required missing capabilities fail closed and prevent a diagnosis from becoming sufficient.
- Optional/adaptive capability gaps remain non-blocking but visible.
- Opaque registries report `UNKNOWN` coverage instead of falsely claiming missing capabilities.
- Added explicit `NOT_REGISTERED` runtime capability result and provenance tracking.
- Added `AgentState.capability_coverage` and `missing_diagnostic_capabilities`.
- LangGraph orchestration routing aligned: `terminate` routes through `evaluate_hypotheses` before reaching `diagnose`.
