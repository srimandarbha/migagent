# v2.12.3

## Taxonomy & Policy Decoupling
- Decoupled `GUEST.WINDOWS.VSS` from CBT into dedicated `policies/guest.windows.vss.yaml` and `skills/guest/windows-vss/skill.md`.
- Separated `VMWARE.VCENTER.CONNECTIVITY` (TCP 443 / SSL thumbprint) from `VMWARE.ESXI.CONNECTIVITY` (TCP 902/NFC/443).
- Added dedicated policies and skills for 16 failure taxonomy classifications:
  - Windows VSS, Hivex registry corruption, BitLocker encryption/VMK metadata, KubeVirt EFI/BIOS firmware conflict, Linux Btrfs filesystem, VDDK transport permission Error 13, VDDK NBD data source export, CD-ROM VMX entry, virt-v2v OOM, argument list E2BIG, Windows NTFS filesystem read-only, disk image resize failure, VirtIO storage drivers, VMDK datastore path, and VMware credentials unauthorized.

## Generic Declarative Hypothesis Engine
- Replaced hardcoded Python `if/elif` hypothesis logic in `MigrationFailureEngine._hypotheses()` with a declarative schema in policy YAML files (`hypotheses:`).
- Evaluates `supporting.all`, `supporting.any`, `contradicting.all`, and `contradicting.any` against live facts.
- Explicit status tracking: `SUPPORTED`, `CONTRADICTED`, and `UNTESTED`.
- First-class contradiction handling: contradictory facts immediately exclude mechanisms and automatically populate `diagnosis_basis['excluded_mechanisms']` with provenance evidence IDs.

## Capability & Parameter Contract Validation (P0)
- Hardened `calculate_coverage` to validate at both the capability ID and parameter contract level (`capability`, `domain`, `signal`, and required parameters).
- Created `engine/integrations/contracts.py` with `CapabilityContractRegistry` and schemas for `observability.search`, `metrics.query`, etc.
- Added contract support inspection to `InMemoryCapabilityRegistry` (`supports_contract(capability, domain, signal)`). If a capability is registered but lacks the required signal contract, coverage fails closed with `COVERAGE_BLOCKED`.
- Exposed structured `contract_details`, `missing_required_contracts`, and `missing_optional_contracts`.

## Fact Ontology & Policy Compiler (P0)
- Created canonical `FactRegistry` in `engine/rules/facts.py` with strongly-typed definitions across storage, network, vmware, conversion, guest_os, and ocv domains to prevent vocabulary drift.
- Created `engine/rules/policy_validator.py` compiler/linter that verifies:
  - Skill markdown existence on disk
  - Capability parameter schemas against `GLOBAL_CONTRACT_REGISTRY`
  - Hypothesis and decision readiness fact references against `FACT_REGISTRY`
  - Adaptive investigation rules and fact references.
- Verified 100% of all repository policies pass validation.

## Evidence & Observation Normalization (P0)
- Introduced `Observation` model in `engine/contracts/models.py` capturing fact, resource, timestamp, observed_at, freshness_seconds, reliability, confidence, value, correlation_id, and provenance.
- Enriched `Evidence` with temporal freshness calculation, resource, and value extraction in `InvestigationTool.collect()`.
- Fixed evidence reference aggregation in `_hypotheses()` and `_diagnosis_basis()`: replaces `refs = {e.fact: e.id}` with `refs: dict[str, list[str]]`, preserving all supporting and contradicting evidence IDs when multiple observations report the same fact.

## Guarded LLM Capability Gate (P0)
- Hardened `parse_advisory()` to validate all suggested investigations against `GLOBAL_CONTRACT_REGISTRY` and registered capabilities.
- Unregistered capabilities or invalid parameter schemas are flagged with explicit `validation_error` and prohibited from safe execution paths.
