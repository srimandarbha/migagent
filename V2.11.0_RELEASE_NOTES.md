# Migration Failure Agent v2.11.0

## Operational learning lifecycle

### Problem addressed
A failure absent from both SRE Tracker and RHOKP is not an infrastructure error. It is either a first-seen knowledge gap or, when the same signature occurs again, a recurring operational knowledge gap. The agent must not infer a fix merely because an SRE previously performed an action.

### Added
- `engine/memory/recurrence.py`
  - deterministic base failure signature
  - evidence signature
  - recurrence correlation contract
- `engine/rules/learning.py`
  - deterministic learning promotion policy
- `engine/learning.py`
  - post-action resolution/verification lifecycle
- `correlate_recurrence` LangGraph node
- `AgentState.failure_signature`
- `AgentState.evidence_signature`
- `AgentState.recurrence`
- `AgentState.learning`
- PostgreSQL learning tables:
  - `sre.resolutions`
  - `sre.resolution_evidence`
  - `sre.learning_candidates`
- Additive `failure_cases` recurrence metadata.
- Fixture SRE Tracker support for recurrence and learning tests.

### Safety rules
1. Historical action is not a solution.
2. Resolution is not reusable knowledge until verification passes.
3. Verified candidate knowledge is not validated knowledge until explicitly human validated.
4. Missing history is different from unavailable history.
5. Current evidence has precedence over historical memory.
6. The initial failure workflow remains read-only.
7. Recording a resolution never executes remediation.

### Test result
`68 passed, 2 skipped` in the current build environment. The two skips are the existing compiled-LangGraph tests because LangGraph is not installed in this build environment. The user's `.venv` has LangGraph and should be used for the compiled graph and Kafka validation.
